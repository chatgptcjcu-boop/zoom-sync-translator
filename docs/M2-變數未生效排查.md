# 為什麼 Variables 畫面有設，/health 卻讀不到？

## 真正原因（Railway 機制）

在 Variables 新增／修改變數後，會進入 **Staged changes（暫存變更）**。

| 你做的動作 | 會不會套用新變數 |
|------------|------------------|
| 畫面上看得到變數 | 只代表「已暫存」，不一定已進容器 |
| Deployments → **Redeploy** | ❌ **不會**套用暫存變數（重跑舊設定） |
| GitHub push 觸發部署 | ❌ **不會**套用暫存變數 |
| 專案畫布上的紫色橫幅 → **Details → Deploy** | ✅ **會**套用 |

因此才會出現：

- UI 有 `OPENAI_API_KEY`、`TRANSLATE_PROVIDER=openai`
- `/health` 卻只有 `TRUST_PROXY=1`（較早那次有成功 Deploy 的變數）

官方說明：[Staged changes](https://docs.railway.com/deployments/staged-changes)、[Variables](https://docs.railway.com/variables)

---

## 正確操作（請照做）

1. 打開 Railway **專案畫布**（Canvas，不是 Variables 頁）  
2. 找頂部／畫布上的 **紫色 Staged changes 橫幅**  
3. 點 **Details**，確認有 `OPENAI_API_KEY`、`TRANSLATE_PROVIDER`、`OPENAI_MODEL`  
4. 點 **Deploy**（不要點 Deployments 裡的 Redeploy）  
5. 等部署 Success 後開：  
   https://zoom-sync-translator-production.up.railway.app/health  

期望：

```json
"hasOpenAIKey": true,
"TRANSLATE_PROVIDER": "openai",
"translateProviders": ["openai", "mymemory"]
```

若看不到紫色橫幅：到 Variables 任意改一個值（例如幫 `OPENAI_MODEL` 再存一次）觸發 staged，再回畫布 Deploy。

## 「The train has not arrived」是什麼？

重新部署期間網域暫時沒有健康實例的過渡頁。  
請只用：`https://zoom-sync-translator-production.up.railway.app`  
等 Deploy Success 後再重新整理即可。
