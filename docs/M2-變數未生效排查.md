# 為什麼 Redeploy 後仍只有 mymemory？

## 結論（依目前 /health）

```json
"TRUST_PROXY": "1",          // ✅ 有進到這個 Service
"TRANSLATE_PROVIDER": "(unset)",
"hasOpenAIKey": false,       // ❌ 行程裡沒有 OPENAI_API_KEY
"hasDeepLKey": false
```

代表：

1. **程式與網域沒壞**（能讀 `TRUST_PROXY`、網站可開）  
2. **不是「沒重新發佈」**——發佈成功，只是新行程依然沒帶 OpenAI 變數  
3. **根因：OpenAI 相關變數沒有出現在「正在提供 production 網域的那個 Service」的 Runtime Variables**

常見原因（依機率）：

| # | 原因 | 怎麼確認 |
|---|------|----------|
| 1 | 變數加在**別的 Service／別的 Project** | 點網域旁的 Service，再看 Variables |
| 2 | 變數名拼錯（`OPEN_AI_API_KEY`、`OPENAI_KEY`、`openai_api_key`） | 名稱必須是 `OPENAI_API_KEY` |
| 3 | 加在 **Shared Variables** 但**沒共享給這個 Service** | Shared → 勾選此 Service |
| 4 | 加在 **Preview／其他 Environment**，Production 沒有 | 切到 Production 環境再設 |
| 5 | Raw Editor 格式錯誤、沒按儲存 | Variables 列表要能看到該列 |
| 6 | 值左右有隱藏字元／整段被包在引號裡且異常 | 重新貼上 `sk-...` 純文字、不要加引號 |

---

## 正確設定步驟（請照做一次）

1. 開 Railway → 專案  
2. 點開會綁定  
   `zoom-sync-translator-production.up.railway.app`  
   的那個 **Service**（左側服務卡片）  
3. 上方分頁 **Variables**（不是 Settings 裡的別處）  
4. 用 **Add Variable** 各加一筆（或 Raw Editor 一次貼上）：

```
TRANSLATE_PROVIDER=openai
OPENAI_API_KEY=sk-你的真實金鑰
OPENAI_MODEL=gpt-4o-mini
TRUST_PROXY=1
```

5. 確認列表裡**真的看得到**這三個名字（除了已有的 TRUST_PROXY）  
6. Deployments → **Redeploy**  
7. 開 `/health`，應變成：

```json
"hasOpenAIKey": true,
"TRANSLATE_PROVIDER": "openai",
"translateProviders": ["openai", "mymemory"]
```

---

## 用 Deploy Logs 交叉確認

Deployments → 最新一筆 → **View Logs**，找啟動時類似：

```
[env] TRANSLATE_PROVIDER=openai hasOpenAIKey=true ...
```

若仍是 `hasOpenAIKey=false`，就是變數沒掛上，與程式無關。

---

## 不是這些原因

- ❌ 不是 GitHub 沒推到（新版 `/health` 的 `env` 欄位已在線上）  
- ❌ 不是網域錯（production 網址可回 JSON）  
- ❌ 不是 OpenAI Key「無效」——無效時會是 `hasOpenAIKey: true` 但翻譯失敗；你現在是 **Key 根本不存在於行程**
