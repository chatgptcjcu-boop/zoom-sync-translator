# SyncSub — 整體程序與過程

本文記錄目前正式架構、網址分工、部署／本機流程、設計決策，以及文件索引。  
**給外部測試者請只轉傳：** [給測試者的說明.md](./給測試者的說明.md)（不含自用路徑）。  
**站長私用操作：** [站長自用說明.md](./站長自用說明.md)。

## 1. 產品一句話

SyncSub 是 Zoom 會議旁的 **中日雙語即時字幕中繼**：雙方用 Chrome 開同一房號，各自麥克風經 Web Speech 轉文字，中繼站翻譯後用 Socket.io 推播。Zoom 傳聲音；SyncSub 傳字幕。

**正式網域：** https://zoom-sync-translator-production.up.railway.app  
**程式庫：** https://github.com/chatgptcjcu-boop/zoom-sync-translator

## 2. URL 地圖（同一 Railway 服務）

| 路徑 | 誰用 | 頁面來源 | 翻譯額度 |
|------|------|----------|----------|
| `/` | 對外說明 | `public/index.html` | 無會議室；引導至 `/try` |
| `/try` | 公開測試會議室 | `server/pages/try.html` | **強制 BYOK**（測試者自己的 Gemini Key） |
| `/guest`、`/guest/` | 相容舊連結 | 同上 `try.html` | 同 `/try` |
| `/r/<HOST_LOBBY_TOKEN>` | **站長自用** | `server/pages/host.html` | 伺服器 `GEMINI_API_KEY` |
| `/host.html`、`/try.html`、`/guest.html` | — | 302 → `/` | 避免猜檔名直連 |
| `/health` | 監控／排查 | JSON | — |
| `/api/config` | 前端設定 | JSON（**不回傳**自用路徑） | — |
| 靜態 `/css/*`、`/js/*` | 共用 | `public/` | — |

設計原則：

- 對外只公開「說明 + `/try`」。
- 自用大廳放在 **不易猜測的 token 路徑**，HTML 不放在 `public/` 可直接列目錄的位置。
- `/api/config` 只暴露 `publicGuidePath`、`publicTryPath`，不洩漏 `HOST_LOBBY_PATH`。

## 3. 執行時資料流

```
Chrome（台灣端）                     Railway Node                      Chrome（日本端）
  Web Speech (zh) ──send_speech──▶  房間廣播原文 ──────────────────▶  顯示原文
                                   翻譯佇列（每房串行）
                     BYOK 或伺服器 Key ──▶ Gemini …
                                   推播譯文 ◀──────────────────────▶  顯示日文譯文
  （對稱：日本端 ja → 中文譯文）
```

進房時前端送 `join_room`，含：

- `guestLane: true`（僅 `/try`／`/guest` 頁）：伺服器 **強制** 必須有 `apiKey`，`translator.mode = byok`，永不回退伺服器額度。
- 自用頁：可不帶 Key → `mode = server`，使用環境變數中的 Gemini Key。
- 全域開關 `REQUIRE_CLIENT_API_KEY=true`：連非 guest 通道也強制 BYOK（通常不必開；公開測試已由 `/try` 覆蓋）。

翻譯時（`send_speech`）：若該 socket 為 BYOK，只用客戶端帶上的 Key；否則走 `server/translate.js` 的引擎鏈（預設 Gemini）。

## 4. 目錄與職責

```
zoom-sync-translator/
├── server/
│   ├── index.js          # Express 路由、Socket.io、佇列、啟動 log
│   ├── pages/
│   │   ├── try.html      # 公開測試大廳（強制自備 Key）
│   │   └── host.html     # 自用大廳（伺服器額度）
│   ├── rooms.js          # 房間成員／歷史
│   ├── translate.js      # Gemini／DeepL／OpenAI／MyMemory
│   └── env.js            # 多別名讀環境變數
├── public/
│   ├── index.html        # 對外測試說明（非會議室）
│   ├── css/app.css
│   └── js/app.js         # 共用會議室邏輯（guestLane / hostLane）
├── docs/                 # 本文件與里程碑
├── .env.example
└── package.json
```

前端旗標：

- `window.__SYNCSUB_GUEST__` 或路徑 `/try`、`/guest` → `guestLane`
- `window.__SYNCSUB_HOST__` 或路徑 `/r/...` → `hostLane`（分享連結時保留 pathname，避免改寫成公開 `/`）

## 5. 環境變數（Railway / 本機）

見根目錄 `.env.example`。與「兩組入口」最相關：

| 變數 | 用途 |
|------|------|
| `GEMINI_API_KEY` | 站長自用／伺服器翻譯額度 |
| `TRANSLATE_PROVIDER` | 預設 `gemini` |
| `HOST_LOBBY_TOKEN` | 自用路徑密鑰；實際路徑 `/r/<token>` |
| `REQUIRE_CLIENT_API_KEY` | 全域強制 BYOK（選用；一般靠 `/try`） |
| `TRUST_PROXY` | Railway 建議 `1` |
| `CORS_ORIGIN` | 正式環境宜鎖網域 |
| `PORT` | 本機預設 `3100`；Railway 注入 |

**切勿**把 `.env` 或真實 API Key 寫進文件、commit、或傳給測試者。

本機啟動時 console 會印：

- 公開說明 `/`
- 公開測試 `/try`
- 自用入口 `/r/...`（標註勿外傳）

## 6. 本機跑起來

```bash
cp .env.example .env   # 填入 GEMINI_API_KEY（自用通道需要）
npm install
npm start
```

| 用途 | 本機網址 |
|------|----------|
| 測試說明 | http://localhost:3100/ |
| 測試會議室（BYOK） | http://localhost:3100/try |
| 自用會議室 | http://localhost:3100/r/<你的 HOST_LOBBY_TOKEN> |
| 健康檢查 | http://localhost:3100/health |

煙測：

```bash
npm run smoke
npm run smoke -- https://zoom-sync-translator-production.up.railway.app
```

## 7. Railway 部署與驗證

1. 推送 `main` → Railway 自動部署（Nixpacks；勿再加會蓋掉 runtime env 的舊 Dockerfile）。
2. Variables：至少 `GEMINI_API_KEY`、`TRANSLATE_PROVIDER=gemini`、`TRUST_PROXY=1`；可自訂 `HOST_LOBBY_TOKEN`。
3. 驗收：
   - `GET /health` → `ok: true`，`env.hasGeminiKey` 對站長額度應為 true。
   - 開 `/` 看到說明，按鈕進 `/try`。
   - `/try` 不填 Key 無法進房。
   - 自用 `/r/<token>` 可不填 Key（用伺服器額度）進房。
4. 詳細部署與排查仍見 [M1-Railway部署指南.md](./M1-Railway部署指南.md)、[M2-Gemini接線.md](./M2-Gemini接線.md)、[為何hasGeminiKey仍false.md](./為何hasGeminiKey仍false.md)。

## 8. 給人測 vs 自己開：操作摘要

### 對外測試（不消耗站長額度）

1. 傳 [給測試者的說明.md](./給測試者的說明.md) 或只傳公開網址 `/`、`/try`。
2. 測試者自備 Gemini Key，雙方同一房號、同一 `/try`。
3. **不要**把 `/r/...` 貼到聊天、郵件、或測試說明。

### 站長正式／自用會議

1. 打開自用路徑（見 [站長自用說明.md](./站長自用說明.md)）。
2. 雙方用自用網址 + 同房號；翻譯走伺服器 Key。
3. 與 Zoom 並排視窗；開始收音。

## 9. 決策與演進（為何這樣做）

| 決策 | 原因 |
|------|------|
| 公開測試與自用入口分離 | 早期單一首頁：別人測會吃站長 Gemini 額度 |
| 先有 `/guest` BYOK | 訪客強制自備 Key；首頁仍用伺服器額度 |
| 再改成 `/` = 說明、`/try` = 測試、`/r/<token>` = 自用 | 首頁不再是「可猜到的主辦大廳」；自用路徑可輪換 token |
| `guestLane` 旗標 | 即使有人改前端，伺服器端仍拒絕無 Key；且不准退回 server mode |
| HTML 放 `server/pages/` | 避免 `express.static` 直接暴露 `host.html` |
| `/guest` 仍有效 | 相容已分享的舊連結，內部等同 `/try` |
| `REQUIRE_CLIENT_API_KEY` 保留 | 緊急時可全域關伺服器額度；日常不必開 |
| `/api/config` 不回傳 host path | 減少前端／網路面板洩漏自用 URL |

相關技術說明：[BYOK-自備APIKey.md](./BYOK-自備APIKey.md)。

## 11. 已知限制（摘要）

- 不擷取 Zoom 對方聲音；對方也必須開 SyncSub 並說話。
- Web Speech 依賴 Chrome／Edge 與 HTTPS（或 localhost）。
- 自用路徑靠「難猜 token」，不是完整帳號登入；勿外傳、可定期更換 `HOST_LOBBY_TOKEN`。
